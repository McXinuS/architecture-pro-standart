| R1 | Все сервисы работают 24/7 и доступны в 99,9 % случаев |
| R2 | При сбое в ЦОД сервисы продолжают работать и выдерживают требуемую нагрузку |
| R3 | Заявки клиентов не теряются, если АБС временно недоступна или перегружена |

| S1 | Для системы есть документация для дальнейшего расширения |

| +R2 | Для очередей сообщений используется Kafka, текущая платформа интернет-банка с ней несовместима |

### <a name="_qmphm5d6rvi3"></a>**Решение**

Диаграмма контекста: [c4-context.drawio](c4-context.drawio)

Диаграмма контейнеров: [c4-container.drawio](c4-container.drawio)

**Интернет-банк**

- **Сервис депозитов** — новый микросервис на ASP.NET Core с базой MS SQL. Он отдаёт ставки и принимает заявки от интернет-банка и сайта, отправляет СМС-коды и обменивается данными с АБС через Kafka. Отдельный сервис нужен, потому что монолит интернет-банка несовместим с Kafka (+R2), а функционал СМС находится в ядре платформы подрядчика (S2). Перевод на микросервисы ограничен депозитами (+R5). Команда интернет-банка знает .NET, база MS SQL уже используется в банке (+R1).
- **Веб-приложение интернет-банка** — существующий монолит. В нём появляются страницы депозитов, данные для них приходят из Сервиса депозитов по REST. Текущие платежи и счета работают как раньше.
- Сервис депозитов хранит копию ставок у себя, поэтому ставки показываются быстро и без запросов в АБС (P1, +R3).
- Сервис депозитов не хранит состояние в памяти и разворачивается в обоих ЦОД за балансировщиком. Для MS SQL настраивается репликация между ЦОД. Так выполняются R1, R2 и P2.

**АБС**

- **Интеграционный сервис АБС** — новый сервис на Java Spring Boot. Он читает заявки из Kafka и записывает их в АБС через процедуры PL/SQL, а новые ставки и статусы заявок публикует в Kafka. В команде АБС есть специалисты с опытом Java (+R1).
- **БД АБС** — появляются таблицы и процедуры для ставок, заявок и согласования специальных ставок. Ставки перестают храниться в Excel (F7). Доступ к данным разграничен ролями (+R7).
- **Клиент АБС** — новые экраны для ведения ставок и обработки заявок из интернет-банка.
- АБС отправляет СМС о ставке и открытии депозита через СМС-шлюз, как сейчас.

**Интеграция**

- Сервис депозитов и АБС обмениваются данными только через Kafka. Если АБС перегружена или недоступна, заявки ждут в Kafka, и Интеграционный сервис передаёт их в АБС в своём темпе. Так интернет-банк не работает с АБС напрямую (+R3, R3), а нагрузка на АБС не растёт резко (+R4).
- Ставки ведутся только в АБС и расходятся по сайту, интернет-банку и кол-центру через Сервис депозитов и Kafka (+R8).
- Система кол-центра получает заявки с сайта из Kafka. Платформа кол-центра написана на Java и допускает расширение (UC2).
- Сайт и интернет-банк работают по HTTPS, сервисы между собой по REST/HTTPS (+R6).
- API Сервиса депозитов описывается в OpenAPI, это основа документации для расширения (S1).

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

1. **Интернет-банк вызывает АБС напрямую по API.** Отклонено: АБС перегружена и масштабируется только вертикально, при её сбое заявки будут теряться (+R3, +R4, R3).
2. **Реализовать депозиты внутри монолита интернет-банка.** Отклонено: монолит несовместим с Kafka, СМС пришлось бы дорабатывать в ядре подрядчика, монолит нельзя масштабировать отдельно (+R2, S2, P2).
3. **Вести ставки в новом отдельном сервисе ставок, а не в АБС.** Отклонено для MVP: сотрудники бэк-офиса уже работают в АБС, там же удобно сделать согласование ставок по заявке. Отдельный сервис ставок можно рассмотреть для целевого решения.
4. **Обмен Сервиса депозитов с АБС по REST вместо Kafka.** Отклонено: при недоступности АБС заявки будут теряться, а пики онлайн-заявок сразу попадут в АБС (R3, +R4).

**Недостатки, ограничения, риски**

- Основные доработки приходятся на АБС: таблицы, процедуры, экраны и Интеграционный сервис. Команда АБС из 20 человек может стать узким местом.
- Kafka — новая технология для банка. Нужны экспертиза и эксплуатация кластера в двух ЦОД.
- Ставки в Сервисе депозитов — копия. После изменения в АБС они обновляются с небольшой задержкой.
- Веб-приложение интернет-банка остаётся монолитом в одном ЦОД. При его сбое страницы депозитов тоже недоступны, поэтому R1 и R2 полностью выполняются только для Сервиса депозитов.
- Текущие платежи интернет-банка по-прежнему работают напрямую с БД АБС. Это решение их не меняет.
- Системе кол-центра нужна доработка для чтения заявок из Kafka, её делает подрядчик или специалисты команды АБС с опытом Java.
- СМС-шлюзу нужен API для Сервиса депозитов, сейчас с ним работает только АБС.
- Персональные ставки для клиентов интернет-банка рассчитываются в АБС вместе с базовыми. Это допущение, его нужно подтвердить с бизнесом.
