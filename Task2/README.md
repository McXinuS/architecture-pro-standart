# Задание 2. FURPS+ таблица

Требования собраны для MVP открытия депозитов и для кредитного направления. Архитектурно значимые требования находятся в разделе +R. Требования, которые я добавил сам, отмечены в комментарии словом «Добавлено».

| Код | Требования | Комментарий |
|-----|------------|-------------|
| F | **Функциональные (Functionality)** | |
| | *Депозиты (MVP)* | |
| F1 | Сайт показывает список депозитов с актуальными ставками | |
| F2 | На сайте клиент оставляет заявку на депозит: Ф. И. О. и номер телефона | |
| F3 | Заявка с сайта попадает в систему кол-центра. Менеджер кол-центра изучает её, звонит клиенту и может предложить особые условия | |
| F4 | После звонка новый клиент приходит в отделение для идентификации | Банк не может принять нового клиента без личной проверки документов |
| F5 | Интернет-банк показывает список депозитов с актуальными ставками и персональные ставки клиента | |
| F6 | В интернет-банке клиент подаёт заявку на депозит: выбирает счёт и сумму и подтверждает операцию СМС-кодом | |
| F7 | Ставки по депозитам хранятся в информационной системе, а не в Excel-файлах. С ними работают бэк-офис депозитов и бэк-офис кредитов | В задании предложено сделать это в АБС вместе с согласованием ставки по заявке |
| F8 | Менеджер бэк-офиса обрабатывает заявку и подтверждает условия депозита в АБС | В MVP заявки обрабатываются по старому процессу |
| F9 | Клиент получает СМС после подтверждения ставки и после открытия депозита | |
| | *Кредиты* | |
| F10 | Сайт и интернет-банк показывают доступные кредиты с актуальными условиями | Условия кредитов хранятся в Кредитном конвейере |
| F11 | На сайте клиент оставляет заявку на кредит: Ф. И. О. и номер телефона. Если он укажет паспортные данные, то сразу получит решение об одобрении | Клиент новый, поэтому для скоринга есть только данные Бюро кредитных историй |
| F12 | После заявки на сайте клиент получает СМС с приглашением в отделение для идентификации и получения кредита | |
| F13 | В отделении менеджер продолжает работать с заявкой, поданной на сайте. Для полностью нового клиента он создаёт новую заявку | |
| F14 | Интернет-банк показывает клиенту предодобренное предложение по кредиту | |
| F15 | В интернет-банке клиент подаёт заявку на кредит: указывает счёт зачисления и данные заявки и подтверждает операцию СМС-кодом | |
| F16 | По заявке на предодобренное предложение скоринг проводится повторно по упрощённой процедуре | |
| F17 | Клиент получает СМС при изменении статуса заявки на кредит | |
| U | **Удобство использования (Usability)** | |
| U1 | Сайт и интернет-банк соответствуют системе дизайна банка: привычные цвета и брендированные элементы | |
| U2 | Клиент видит в интернет-банке статус своей заявки на депозит или кредит | Добавлено. Основные клиенты банка — люди старшего возраста. Если статус виден, они будут реже звонить в кол-центр |
| R | **Надёжность (Reliability)** | |
| R1 | Все сервисы работают 24/7 и доступны в 99,9 % случаев | Сейчас интернет-банк этого не обеспечивает |
| R2 | При сбое в ЦОД интернет-банк продолжает работать и выдерживает требуемую нагрузку | Сейчас всё работает в одном ЦОД на одной группе серверов. Есть резервный ЦОД, на который можно переключиться |
| R3 | Заявки клиентов не теряются, если АБС временно недоступна или перегружена | Добавлено. АБС перегружена, поэтому заявки нужно принимать независимо от неё |
| P | **Производительность (Performance)** | |
| P1 | Отклик по операциям в интернет-банке занимает миллисекунды. Справочные данные при платежах загружаются меньше чем за секунду | Сейчас справочные данные загружаются больше секунды |
| P2 | Сервисы масштабируются горизонтально, запросы распределяются между серверами, приложениями и ЦОД | |
| P3 | Решение по кредитной заявке из интернет-банка или с сайта клиент получает в течение одного дня, если данных для решения достаточно | Сейчас решение занимает около недели |
| P4 | Заявки по предодобренным предложениям обрабатываются в течение того же рабочего дня | |
| S | **Поддерживаемость (Supportability)** | |
| S1 | Для системы есть документация для дальнейшего расширения | |
| S2 | Новый функционал СМС в интернет-банке реализует команда банка без доработки ядра платформы подрядчиком | Функционал СМС находится в ядре платформы, его доработку делает подрядчик |
| +R | **Ограничения (Restrictions)** | |
| +R1 | Используются технологии, которые уже есть в банке: MS SQL, Oracle. Новые технологии должны быть совместимы с текущими платформами разработки, а у сотрудников должна быть экспертиза хотя бы на уровне языков программирования | |
| +R2 | Для очередей сообщений используется Kafka | Текущая платформа интернет-банка несовместима с Kafka |
| +R3 | В новых процессах интернет-банк не работает напрямую с БД и API АБС | АБС перегружена. Онлайн-заявки могут поставить под угрозу работоспособность банка |
| +R4 | АБС масштабируется только вертикально | Ограничение базы данных АБС |
| +R5 | Интернет-банк можно перевести на микросервисную архитектуру, но пока только в части открытия депозитов | |
| +R6 | Данные при передаче с сайта и в интернет-банке защищены шифрованием трафика | С сайта передаются чувствительные персональные данные |
| +R7 | Сотрудники депозитов и сотрудники кредитов не имеют доступа к данным друг друга | Добавлено. Требование безопасности из описания процесса открытия депозита в задании 1 |
| +R8 | Сайт, интернет-банк и кол-центр получают ставки из одного источника | Добавлено. Иначе клиенту в разных каналах назовут разные ставки |
| +R9 | Обмен заявками между АБС и Кредитным конвейером идёт раз в сутки, ускорить его невозможно | |
| +R10 | Кредитный конвейер и Система кредитного скоринга масштабируются горизонтально и работают 24/7 | |
| +R11 | Система кредитного скоринга не выполняет предрасчёты скорингов | В рабочие часы на неё приходится повышенная нагрузка |
