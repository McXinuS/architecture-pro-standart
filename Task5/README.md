### <a name="_b7urdng99y53"></a>**Название задачи:** ADR-3. Заявка на кредит онлайн
### <a name="_hjk0fkfyohdk"></a>**Автор:** Андрей Шаповалов
### <a name="_uanumrh8zrui"></a>**Дата:** 02.11.2026

Решение реализуется в течение года после MVP открытия депозитов ([ADR-1](../Task3/README.md)) и использует его элементы: Kafka, СМС-шлюз с API и подход с отдельным сервисом в контуре интернет-банка.

### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

| № | Требование |
| :-: | :- |
| R1 | Все сервисы работают 24/7 и доступны в 99,9 % случаев |
| R2 | При сбое в ЦОД сервисы продолжают работать и выдерживают требуемую нагрузку |
| R3 | Заявки клиентов не теряются, если смежные системы временно недоступны или перегружены |
| P1 | Отклик по операциям в интернет-банке занимает миллисекунды |
| P2 | Сервисы масштабируются горизонтально, запросы распределяются между серверами и ЦОД |
| P3 | Решение по кредитной заявке из интернет-банка или с сайта клиент получает в течение одного дня |
| P4 | Заявки по предодобренным предложениям обрабатываются в течение того же рабочего дня |
| S1 | Для системы есть документация для дальнейшего расширения |
| S2 | Новый функционал СМС реализует команда банка без доработки ядра интернет-банка подрядчиком |
| +R1 | Используются технологии, которые уже есть в банке, например MS SQL и Oracle. Новые технологии совместимы с текущими платформами разработки, у сотрудников есть экспертиза в них |
| +R2 | Для очередей сообщений используется Kafka, текущая платформа интернет-банка с ней несовместима |
| +R3 | В новых процессах интернет-банк не работает напрямую с БД и API АБС |
| +R5 | Интернет-банк можно перевести на микросервисы, но пока только в части открытия депозитов. Решение делается после MVP, поэтому ограничение нужно пересмотреть |
| +R6 | Данные при передаче с сайта и в интернет-банке защищены шифрованием трафика |
| +R7 | Сотрудники депозитов и сотрудники кредитов не имеют доступа к данным друг друга |
| +R9 | Обмен заявками между АБС и Кредитным конвейером идёт раз в сутки, ускорить его невозможно |
| +R10 | Кредитный конвейер и Система кредитного скоринга масштабируются горизонтально и работают 24/7 |
| +R11 | Система кредитного скоринга не выполняет предрасчёты скорингов |

### <a name="_qmphm5d6rvi3"></a>**Решение**

Диаграмма контекста: [c4-context.drawio](c4-context.drawio)

Диаграмма компонентов: [c4-component.drawio](c4-component.drawio)

Главная идея: онлайн-заявки идут в Кредитный конвейер напрямую через Kafka, минуя АБС. Суточный обмен с АБС ускорить нельзя (+R9), поэтому иначе решение за один день (P3) и обработку предодобренных заявок в тот же день (P4) не получить.

**Интернет-банк**

- **Сервис кредитов** — новый микросервис на ASP.NET Core с базой MS SQL, по образцу Сервиса депозитов из ADR-1. Он нужен по тем же причинам: монолит интернет-банка несовместим с Kafka (+R2), а СМС-функции находятся в ядре платформы подрядчика (S2). Перевод интернет-банка на микросервисы продолжается после MVP (+R5).
- **API кредитов** отдаёт сайту и интернет-банку условия, предодобренные предложения и статусы, принимает заявки. Условия и предложения хранятся в копии, поэтому страницы открываются быстро и не нагружают конвейер (P1).
- **Обмен с конвейером** публикует заявки в Kafka и получает из неё статусы, решения, условия и предложения.
- **Уведомления** отправляют через СМС-шлюз коды подтверждения и СМС о смене статуса (F12, F17). API СМС-шлюза уже появился в MVP.
- Сервис не хранит состояние в памяти и разворачивается в обоих ЦОД, для MS SQL настраивается репликация (R1, R2, P2). Сайт и интернет-банк работают по HTTPS (+R6).
- Кредиты и депозиты — разные сервисы с разными базами. Так данные направлений разделены (+R7), а команды выпускают изменения независимо.

**Кредитный конвейер**

- **Интеграция с Kafka** — новый обработчик на Java. Camunda позволяет писать такие обработчики, а в IT-отделе есть специалисты, которые их меняют (+R1). Обработчик запускает процесс по каждой заявке из Kafka и публикует статусы, решения, изменения условий и предодобренные предложения.
- **Процессы кредитования** — в Camunda добавляются два процесса. *Экспресс-решение* для заявки с сайта запрашивает скоринг только по данным БКИ и принимает предварительное решение автоматически (F11). *Заявка по предодобренному предложению* запрашивает упрощённый скоринг и сразу ставит задачу менеджеру (F16, P4).
- **Интерфейс сотрудников** — в Camunda Tasklist появляется экран онлайн-заявок для сотрудников отделений. Они видят только задачу идентификации, без кредитного анализа (F13).
- Конвейер масштабируется горизонтально и работает 24/7, поэтому Сервис кредитов может отправлять в него заявки в любое время (+R10).
- Одобренные заявки уходят в АБС текущим суточным обменом. Доработок АБС почти нет — нужны только поля онлайн-заявки (счёт зачисления) в обмене. Интернет-банк с АБС напрямую не работает (+R3).

**Система кредитного скоринга**

- Появляются два режима: скоринг нового клиента только по данным БКИ и упрощённый скоринг по предодобренному предложению. Запросы к БКИ, как и сейчас, идут онлайн.
- Предрасчётов нет (+R11). Предодобренное предложение появляется, когда скоринг клиента уже прошёл по другой заявке. Конвейер сохраняет результат и публикует предложение.

**Интеграция**

- Сервис кредитов и конвейер обмениваются данными только через Kafka. Если конвейер недоступен, заявки ждут в Kafka и не теряются (R3).
- Экспресс-решение тоже идёт через Kafka. Пока клиент ждёт, сайт опрашивает статус заявки в Сервисе кредитов. Обычно решение приходит за несколько секунд.
- API Сервиса кредитов и форматы сообщений в Kafka описываются в OpenAPI и AsyncAPI (S1).

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

1. **Онлайн-заявки создаются в АБС и попадают в конвейер суточным обменом.** Отклонено: заявка дойдёт до конвейера только на следующий день, P3 и P4 не выполнить (+R9). Кроме того, это нагрузка на АБС (+R3).
2. **Сайт и интернет-банк вызывают API Кредитного конвейера напрямую.** Отклонено: монолит интернет-банка не умеет СМС без подрядчика (S2), заявки теряются при недоступности конвейера (R3), а коробочный конвейер пришлось бы открыть для клиентских каналов.
3. **Добавить кредиты в Сервис депозитов.** Отклонено: данные направлений смешаются в одной базе (+R7), сервис превратится в новый монолит, команды будут мешать друг другу.
4. **Синхронный REST-вызов конвейера для экспресс-решения.** Отклонено: при перегрузке конвейера страница сайта зависнет, а заявка может потеряться. Через Kafka клиент получает решение почти так же быстро.
5. **Ночной предрасчёт предодобренных предложений по всем клиентам.** Отклонено: скоринг не должен выполнять предрасчёты (+R11).
6. **Сотрудник отделения продолжает онлайн-заявку в АБС.** Отклонено: для этого онлайн-заявку нужно копировать в АБС, а потом снова передавать в конвейер суточным обменом. Получатся дубли и задержка на сутки.

**Недостатки, ограничения, риски**

- Деньги зачисляются только после суточного обмена конвейера с АБС, то есть на следующий день после одобрения (+R9). Клиент быстро получает решение, но не деньги.
- Сотрудникам отделений нужен доступ к Кредитному конвейеру для онлайн-заявок. Это новая роль и обучение, сотрудник работает в двух системах.
- Решение на сайте предварительное, оно построено только на данных БКИ. После идентификации и полного скоринга итоговое решение может отличаться.
- Предодобренные предложения есть только у клиентов, по которым скоринг уже проводился. У новых клиентов интернет-банка их не будет.
- Онлайн-заявки увеличивают нагрузку на скоринг в рабочие часы. Это реальные заявки, а не предрасчёты, но нужен запас мощности (+R10).
- Перевод на микросервисы выходит за рамки депозитов (+R5). Это нужно согласовать с командой интернет-банка.
- Конвейер — коробочное решение подрядчика. Новые процессы и обработчик делает IT-отдел банка, но обновления платформы нужно согласовывать с подрядчиком.
- Паспортные данные с сайта — персональные данные. Их передача защищена HTTPS, а хранение в Сервисе кредитов требует шифрования и ограничения доступа.
